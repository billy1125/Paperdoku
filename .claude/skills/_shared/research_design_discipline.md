# 研究設計紀律（前段 pipeline 共用）

> Paperdoku **研究設計 pipeline（前段）** 的共用紀律。`research-brainstorming-zh`、`literature-scoping-zh`、`scholar-evaluation-zh`、`hypothesis-generation-zh` 四個 skill 以 `../_shared/research_design_discipline.md` 引用，勿各自重寫。本檔把最高鐵律 `anti_leakage.md` 延伸到「發散/生成」情境。

## 一、提案非發現（最高原則）

前段一切產出——研究方向、機制假說、缺口宣稱、可信度評分、假設——都是**提案（proposal）**，不是已證實的結論。收斂到可檢驗的研究問題就是前段的終點；驗證留給後段的閱讀/審查與實際研究，前段不做、也不能宣稱驗證。

## 二、主張分類標記

任何一句話，先想清楚它屬於哪一類，並在輸出中區分（不混為一談）：

| 類別 | 意思 |
|---|---|
| idea（構想） | 一個候選方向或問題，尚未主張為真 |
| assumption（假設前提） | 推論所依賴、但未經查證的前提 |
| prediction（預測） | 「若某假說成立，則應觀察到 X」 |
| located-evidence（已定位證據） | 有 MCP 回傳或使用者原文可查的具體來源支持 |
| decision（決策） | 由使用者（accountable owner）拍板的取捨 |

只有 **located-evidence** 能附來源當「證據」用；其餘一律講明是構想/前提/預測。

## 三、anti-leakage 延伸（生成情境）

發散階段**可以自由生成構想**，這與 `anti_leakage.md` 不衝突——因為構想被標為 idea，不是對文獻的事實陳述。但一旦談到**文獻說了什麼、某數據、某引用、某研究缺口**，就回到最高鐵律：

- 只能引用 **MCP 實際回傳**（`semantic-scholar`／`openalex`）或**使用者提供的原文**；
- **禁止**憑模型記憶捏造標題、作者、引用數、結論或「我印象中有人做過」；
- 不確定就標為構想或 `未定位到來源`，不腦補成事實。

完整鐵律見 `anti_leakage.md`。

## 四、反缺口膨脹

「找到研究缺口」是前段核心產出，最容易誤把「我沒查到」講成「沒人做過」：

- 用「**在本次搜尋範圍內尚未定位到直接證據**」，不用「從未有人研究」「這是全新領域」；
- **記錄搜尋邊界**：查了哪些資料源、關鍵字、年份、篩選條件——缺口宣稱的可信度取決於搜尋的完整度；
- 一次不完整的搜尋不能證成新穎性；MCP 未涵蓋、非英文、書籍、極新文獻都可能造成假缺口。

## 五、三件事分離

- **ideation（發想）**：產生問題、機制、替代方案。
- **evidence assessment（證據評估）**：查文獻與資料支持什麼、可信度多高。
- **hypothesis validation（假設驗證）**：需要觀察、預測、適當設計與獨立檢驗——前段做不到。

三者不可互相冒充：一堆構想不等於有證據；有支持文獻不等於新機制已被驗證。

## 六、評估只是決策輔助

打分、排序、評估矩陣是**追溯性的決策輔助**，不自動選 winner：

- 評分前先定義準則、方向與權重，看到結果後不回頭改權重；
- 保留原始評分、不確定範圍、少數意見與棄權，不用平均分數掩蓋否決（ethics/feasibility 閘門）；
- 最終取捨由使用者負責，並記錄理由與被否決的替代方案。

## 與其他共用規範的關係

- 最高鐵律、禁記憶補完 → `anti_leakage.md`
- 缺漏怎麼標、語氣依可讀程度收 → `confidence_language.md`
- 跨篇衡量證據強弱的等級 → `evidence_hierarchy.md`
- 假設/方法/結果分離、不從係數猜支持 → `hypothesis_support_discipline.md`
- skill 間交接與前後段橋接 → `handoff.md`
