# 論文研究邏輯審查

批量審查學術論文的研究邏輯：理論基礎、假設建構品質、實證支持狀態。優先閱讀理論、假設、結果與結論章節；跳過方法、統計技術等低價值部分。輸出以 Markdown 格式呈現，預設語言為繁體中文。

## 開場詢問

> 邊界自檢：本 skill 是**評估型**——焦點在假設建構邏輯與支持狀態，刻意跳過方法/抽樣/統計細節。若使用者其實要的是綜整、研究缺口、未來方向或文獻回顧撰寫，改用 `literature-review-organizer`；要抽單篇方法架構改用 `method-extraction-social-science`。不確定時先確認，不硬做。

收到論文後，先問使用者：

> 請問你主要想達成什麼目的？
>
> 1. **支持狀態快速彙整**：只需知道哪些假設被支持或不支持（適合快速確認）
> 2. **假設邏輯完整審查**：評估每個假設的建構邏輯品質與實證支持狀態（預設）
> 3. **研究架構深度分析**：包含變數關係整理、理論貢獻評估與跨論文模式分析（適合深入比較）

根據選擇調整輸出內容：

| 選擇 | 輸出內容 |
|---|---|
| 1 支持狀態快速彙整 | 論文總結表 + 每篇支持/不支持清單 |
| 2 假設邏輯完整審查 | 論文總結表 + 單篇綜合註釋（含邏輯品質）+ 批量綜合 |
| 3 研究架構深度分析 | 選項 2 全部 + 變數關係整理 + 理論貢獻評估 + 跨論文模式分析 |

## 工作流程

確認目的後，依下列順序執行，不跳步：

1. 取得與清點論文，初步篩選（細節見 `references/extraction-steps.md`）
2. 尋找高價值部分（搜尋關鍵字見 `references/extraction-steps.md`）
3. 提取研究架構（變數、假設、理論框架）
4. 評估假設建構邏輯（前提、機制、預期方向、邏輯品質）
5. 確定假設支持狀態（7 種分類見 `references/extraction-steps.md`）
6. 總結研究結果（發現、理論貢獻、實務意義）
7. 整理論文檔案（規則見 `references/extraction-steps.md`）

選項 1 只執行步驟 1–2、步驟 5–6。

輸出格式見 `references/output-template.md`。

## 操作原則

1. **選擇性閱讀**：重點在理論、架構、假設、結果、討論、結論章節
2. **跳過低價值章節**：引言、文獻綜述、方法、測量、統計技術等，除非直接影響假設邏輯或支持判斷
3. **謹慎對待假設支持狀態**：不僅依係數符號推斷，需有顯著性資訊才能判斷
4. **區分假設邏輯與實證結果**：兩者保持獨立，不混淆
5. **標記不確定性**：PDF 提取不完整或結果含糊時，填「根據現有文字無法確定」
6. **保留術語**：使用論文原有變數名稱，必要時加中文說明
7. **跨篇結論衝突時依證據強度加權**：標出各篇研究設計的證據等級，優先採信等級高且偏誤低者，見 `../_shared/evidence_hierarchy.md`（與 `../_shared/risk_of_bias.md` 併用）

## 核心限制

- 不根據係數符號猜測支持狀態，需有作者明示的顯著性資訊
- 不把方法論細節誤寫入研究結果
- 非實證研究論文在總表中標明性質，不強行套用假設架構
- 資訊不足時標記不確定，不捏造

## 上下游交接

- **產物**：論文總結表與綜合說明寫成 markdown 存到 `reports/`（檔名依主題＋`logic-review`，見 `../_shared/paper_naming_convention.md`）。
- **上游**：PDF 先經 `source-document-extraction` 抽成 `extracted/*.md` 再讀。
- **下游**：要綜整/研究缺口/寫回顧改用 `literature-review-organizer`；要逐篇方法架構改用 `method-extraction-social-science`（互補的兩半）。鏈見 `../_shared/handoff.md`。
