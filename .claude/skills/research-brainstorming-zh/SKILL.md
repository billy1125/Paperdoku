# 研究發想技能（Scientific Brainstorming）

研究設計 pipeline（前段）的入口。用途是**發散**——創造、整理、挑戰並透明化排序候選研究方向，交出一份可供使用者決策的提案清單。**每個產出都是提案（proposal），不是發現。** 本 skill 遵守 `../_shared/research_design_discipline.md`（提案非發現、主張分類標記、anti-leakage 延伸、反缺口膨脹、三件事分離）與 `../_shared/anti_leakage.md`、`../_shared/output_language.md`、`../_shared/confidence_language.md`。

創意方法能改變參與方式與構想產量，但**沒有任何方法能普遍提升原創性、有用性或科學效度**。方法只是「合目的的流程選擇」，不是創意保證。

## 適用情境

- 「幫我發想幾個可以做的研究方向／題目」
- 「這個現象有哪些可能的研究切入點／機制假說」
- 「我想開一個新研究，但還沒有明確方向」
- 「幫我把這批粗略想法整理、挑毛病、排優先序」

不適用（請改路由）：收斂成可檢驗假設 → `hypothesis-generation-zh`；找既有文獻 → `paper-search`；系統盤點與定缺口 → `literature-scoping-zh`；讀懂/審查/綜整手上論文 → 後段 pipeline。

## 核心操作規則

1. **主張分類標記**：把每一項標為 idea／assumption／prediction／located-evidence／decision，不混為一談（見共用紀律）。
2. **先獨立生成再曝光**：先自己（或請使用者各自）產生一輪構想，再互相參照，降低被第一個答案或範例錨定。若使用者已給既有想法，先原樣登錄、標為既有錨點，再刻意加生成其他方向。
3. **保留少數意見與不確定性**：不確定、反例、負面證據、棄權都要留著，不被多數意見蓋掉。共識不等於真理，票數不等於效果量。
4. **評分前先定準則**：先定義評估準則、方向與權重，再打分；打完不因結果回頭改權重。評分只是決策輔助，**不自動選 winner**。
5. **文獻查證接 MCP**：任何「文獻說過／已有人做」的宣稱，只能來自 `paper-search`（MCP 實際回傳）或使用者提供原文，禁止憑記憶。查證後再開一輪發散，降低早期錨定又不把「沒查到」當缺口。
6. **閘門優先於分數**：ethics／feasibility／dual-use 等閘門一觸即停，高創意分數不能覆蓋閘門。

## 工作流程

### 步驟 1：界定議題（scope）

寫下一個**焦點問題**，並記錄：目的、對象（audience）、決策負責人、時間範圍；in-scope／out-of-scope 主題；真實／假定／可協商／未知的限制；目前已知與未解的觀察。

若請求涉及病人個案處置、規避監管、有害最佳化或可操作的 dual-use 細節，**停止發散**，導向適當專業或機構程序。

### 步驟 2：刻意多元化視角

盤點該納入哪些方法學／領域／實作／統計／安全／倫理／利害關係人視角，並講明誰的視角在場、缺席或結構性弱勢。多元不保證創意，但能減少盲點。

### 步驟 3：獨立生成

用同一組中性提示產生初始構想。每個構想登錄：穩定 ID＋一句話陳述、來源（human／AI-assisted／literature-inspired／mixed）、依賴的假設、預測會觀察到什麼、不確定性、可能反證。生成手法（假設反轉、尺度移轉、跨域類比、SCAMPER、形態分析、premortem 等）見 `references/brainstorming-methods.md`。

### 步驟 4：不即評價地分享與澄清

先把構想匯集、以穩定 ID 呈現，只澄清語意不辯護、不打分。問：少了什麼？什麼與主流框架矛盾？聽完別人後哪個構想變得沒那麼理所當然？

### 步驟 5：結構化分群

依明確關係分群（共同結果／機制／對象／尺度／方法），保留原始 ID 與文字，記錄合併與拆分。措辭相近不等於語意等價，假設/介入/對象/預測不同就分開留。

### 步驟 6：定義透明準則並評分

評分前先定義每個準則的名稱、方向、量尺錨點、所需證據、權重與設定者。常見維度：資訊增益與可辨別預測、與焦點問題的相關性、相對於**已查文獻**（非只相對於在場者）的原創性、可行性/資源/可逆性、方法嚴謹度、倫理/安全/公平/dual-use、結果為 null 時的價值。不確定用範圍或信心標記表達，不用平均分掩蓋否決。準則、評分與敏感度分析細節見 `references/idea-evaluation.md`。

### 步驟 7：對抗式檢視

為每個入選構想指派一位**非原提出者**的檢視者，問：什麼觀察會讓它變錯或無資訊？哪個替代解釋能符合同樣的預測結果？有無隱藏依賴、測量失敗、混淆或選擇效應？是否被權威/錨定/技術吸引力驅動？會不會造成傷害、加劇不公或被誤用？記錄回應、緩解、殘餘不確定與是否修訂——不是只記 pass/fail。

### 步驟 8：文獻與證據查核（接 paper-search）

把構想轉成可搜尋概念，透過 `paper-search` 查 MCP，記錄查詢/日期/資料源/篩選邊界，並區分：直接相關證據／間接類比／衝突或 null 證據／專家意見／**本次搜尋尚未定位到直接證據**。查核後刻意再開一輪短發散。反缺口膨脹見共用紀律。

### 步驟 9：可行性、嚴謹與倫理閘門

推進任一構想前，辨識該走的領域審查（人體/動物/生物安全/資料治理/出口管制/臨床/環境）。閘門結果記為 not-assessed／review-required／redesign-required／stop 等。倫理或可行性疑慮可要求重設計、受控處理或停止；高創意分數不覆蓋閘門。

### 步驟 10：決策與日誌

由使用者（accountable owner）記錄：考慮過的候選與準則/權重、原始評分/不確定/異議/棄權、文獻查核與日期、閘門結果、決策與理由、被否決的替代方案、重訪觸發條件。並正確標示下一步：進一步搜尋、諮詢、模擬、pilot 設計、收斂假設或不行動。日誌不在結果已知後回頭改寫，只追加更正。

## 輸出格式（產物）

書面成品寫成 markdown 存到 `research-design/<主題>-brainstorm.md`（`<主題>` 用簡短英數或中文主幹）：

1. **焦點問題與 scope**
2. **發想登錄表**：| ID | 一句話構想 | 類別標記 | 來源 | 依賴假設 | 預測觀察 | 不確定/反證 |
3. **分群結果**
4. **評估矩陣**：準則定義＋逐項評分（附不確定範圍）＋敏感度提示；不自動選 winner
5. **對抗式檢視摘要**
6. **文獻查核摘要**（接 paper-search，含搜尋邊界）
7. **決策日誌與建議下一步**

## 上下游交接

- **本 skill 是前段 pipeline 入口**（上游：無）。
- **下游**：查既有文獻 → `paper-search`；把候選方向收斂成可檢驗假設 → `hypothesis-generation-zh`；要系統盤點文獻與缺口 → `literature-scoping-zh`。
- 收尾時建議自然的下一步並點出可傳的產物（如「已產出 3 個候選方向，要查文獻可用 paper-search，要收斂成假設可用 hypothesis-generation-zh」），但不自動執行。完整鏈見 `../_shared/handoff.md`。
