# panel 模式:多視角審查面板

目的:模擬**多位獨立審查者**各以不同視角評同一篇,再由「主編」綜合,減少單一審查者的盲點與偏好。借 ARS 的多審稿人 + 主編設計。適合重要稿件、或想看不同立場如何評同一篇。

> 預設是單一審查者(見 `SKILL.md`)。使用者要「多位審查者/面板/不同角度都看看」時才切本模式。**代價**:輸出較長、耗 token,不是每篇都需要。

## 流程

1. **設定面板**(預設 3 位,可調):給每位一個**不同的視角/風格**,確保真正互補而非重複。常用組合:
   - 審查者 A —— **方法嚴格派**:火力在設計、測量、分析(面向 4–5 + method-checklist)。
   - 審查者 B —— **理論貢獻派**:火力在貢獻、定位、理論架構(面向 1–3)。
   - 審查者 C —— **發展鼓勵派**:找可救之處、把問題框成可行修改(profile=發展)。
   - (可加)審查者 D —— **實證偏誤派**:專跑 `../_shared/risk_of_bias.md` 六面向。

2. **各自獨立評**:每位**獨立**產出精簡意見(2–4 條關鍵 Major + 建議判決),用同一套八大面向與方法清單,但依其視角聚焦。**不要讓後一位附和前一位**——獨立性是面板的價值來源。

3. **主編綜合(Editorial Synthesis)**:
   - 匯整各審查者意見,標出**共識**(多位都提的 → 高信度)與**分歧**。
   - **判決分歧不機械平均**:若一位建議 Reject、一位 Major、一位 Minor,**明列分歧與各自理由**,再給主編綜合判決並說明為何(通常向較嚴一方靠,除非嚴的一方證據薄弱)。分歧本身是有用訊號,呈現給使用者。
   - 產出一份**綜合審查意見書**(結構同 `assets/report-template.md`,但整合多視角)。

## 輸出格式

```markdown
## 審查面板意見（N 位審查者 + 主編綜合）

### 審查者 A（方法嚴格派）
- 關鍵意見（2–4 條，問題→證據→方向）
- 建議判決：Major Revision

### 審查者 B（理論貢獻派）
- …／建議判決：Minor Revision

### 審查者 C（發展鼓勵派）
- …／建議判決：Major Revision（給修改機會）

### 主編綜合
- 共識：測量效度(A、C 都提)為最關鍵，高信度須處理。
- 分歧：A 傾向 Major、B 傾向 Minor——分歧點在對理論貢獻的評價。
- **綜合判決：Major Revision**（理由：效度屬根本問題，向較嚴一方靠；但研究核心可行，給修改機會）。
```

## 紀律

- **獨立性**:各審查者不得互相附和;視角要真的不同(否則面板無意義)。
- **分歧透明**:判決分歧明列不平均,交使用者判斷。
- 所有 `SKILL.md` 的不可逾越底線(證據優先、對事不對人、建議與嚴重度相符)對每位審查者都適用。
- 這是**同一模型模擬多視角**,不是真正的獨立第二意見;要真正跨模型覆核見 `mode-calibration.md` 的跨模型 note。
