# 核心原則詳細說明

本文件為 SKILL.md 核心原則的詳細規範。

## 原則一：不得臆測

若論文沒有清楚報告某項資訊，須使用以下標記：
- **not reported**：論文完全未提及
- **unclear**：論文有提及但描述模糊
- **inferred with low confidence**：有間接線索，但非明確陳述

禁止補充論文未寫的細節，即使在方法上「理所當然」也不可自行填入。

## 原則二：三者不混淆

以下三個層次須明確區分，不可互換：

| 層次 | 定義 | 範例 |
|---|---|---|
| 研究設計（study design） | 資料取得與因果推論的架構 | survey、experiment、quasi-experiment、panel |
| 量測設計（measurement design） | 構念如何操作化與測量 | 量表來源、題項設計、信效度檢驗 |
| 分析方法（analytical method） | 資料分析所用的統計技術 | regression、SEM、ANOVA、HLM、DID |

## 原則三：方法與結果分離

以下屬於「研究結果」，不是方法的核心內容：
- 假說是否獲得支持
- 迴歸係數方向與顯著性
- 統計量（β、p、t 等）

只有在有助於理解分析流程時（例如說明為何增加某個控制變數），才可附帶提及。

## 原則四：重建分析 pipeline

需依邏輯順序完整呈現分析步驟，例如：

```
資料清理 → 描述統計 → 信度/效度檢驗 → 相關分析 → 主模型估計 → 中介/調節分析 → 穩健性分析
```

不可只抓出一個「主要方法」就結束。若論文分析流程不完整或跳躍，需明確標示。

## 原則五：品質判讀有據可查

- 只能根據論文明確報告的方法資訊進行判讀
- 資訊缺乏時，優先標示為 **reporting unclear**，不可直接判定方法錯誤
- 嚴格區分「真正的方法弱點」與「只是報告不清楚」
- 評等定義與輸出格式詳見 `quality-assessment-rules.md`

## 原則六：輸出可比較

- 使用標準化 method labels，參照 `normalized-method-labels.md`
- 所有論文使用相同欄位名稱，不可每篇自行命名
- 固定欄位順序，確保 comparison-ready 表格可直接對齊
